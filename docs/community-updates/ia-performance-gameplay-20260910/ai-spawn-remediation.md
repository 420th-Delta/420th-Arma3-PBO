# AI lifecycle and spawn remediation

The first pass corrects AI-01, AI-02, SYS-02 and the integrated-test finding AI-06 below. The second review extends construction ownership, corrects artillery admission bookkeeping and propagates the unscheduled spawn-search timeout across its enclosing loops. The contributor's spacing policy remains active for the callers that explicitly adopted rejectable outdoor placement. The ordinary group API requires a ninth argument to opt into that policy; its remaining callers retain the established compact five-metre placement contract. This compatibility correction prevents an occupied 85-metre footprint from silently removing mandatory objective guards, building parties or existing-group reinforcements.

## Final-reserve helicopters

The actual ROTARY worker now supplies its cleanup registration callback to `scSpawnHeli`. The helicopter and each crew member are registered in the pressure controller's owned entities in the same short unscheduled block as engine creation. Cancellation during loadout or crew setup therefore cannot strand a created object between creation and callback execution. The completed return array is also registered idempotently before census tracking. Census membership and cleanup ownership remain separate.

STOP retains its existing epoch and player/Zeus/objective exemptions. It now also checks each crew member's parent vehicle: marking only an aircraft hull `QS_primaryAO_exempt` previously preserved the hull while returning its crew for deletion. The native fixture covers both hull and crew exemptions, including the baseline ownership predicate's negative reproduction. Its returned roster feeds the existing Classic retirement loop: personnel are recycled or deleted, aircraft are destroyed and queued for deferred object cleanup. The existing support-provider sweeps then remove dead/missing pilots. This correction does not change native helicopter loadouts or delete player-controlled vehicles.

## Scheduling and ownership

Terrain searches, water checks, visibility rays and greedy selection no longer run inside one uninterrupted `isNil` block. They can yield through the normal scheduler. Unscheduled callers have a four-millisecond cutoff checked between candidates, now propagated across rows and patterns. Initial occupancy queries and greedy selection are outside those checks, and an individual engine command can exceed the interval. The final atomic block performs fresh occupancy/player checks and appends a claim; it does not repeat terrain or visibility work. A stale layout is rejected if another request committed first. Existing twenty-second claims expire normally.

Expanded admission is server-authoritative. The caller audit found an additional dispatch defect: the GRID module lacked the dedicated-server condition used by Classic and sectors even though its init trigger is broadcast. Each HC could race the server to consume that trigger and independently create a partial or duplicate grid population. GRID now uses the same dedicated-server condition. Primary/Defense, Viper, vehicle reinforcement and ambient creation trace to server activity controllers; city missions and support creation trace to server core/initialization. HCs retain unit/group behavior and normal completed-group ownership transfer. Compact group calls retain their locality behavior. A non-server expanded request returns an empty layout with a diagnostic instead of maintaining an independent claim registry.

These claims are admission reservations, not a transaction spanning arbitrary twenty-second-plus caller delays or arbitrary externally scripted creation. They protect the mission's server admission flow. An HC or mod creating unrelated entities can still place something after the final snapshot; ongoing performance/locality acceptance must measure actual runtime behavior.
