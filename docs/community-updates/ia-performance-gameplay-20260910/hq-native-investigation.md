## Source and API review

`fn_core.sqf` copies the current `QS_aoHQ` object handles into a new cleanup list, passes that list to the deferred worker, waits for the actual Defense script to finish, then waits 30 seconds before direct deletion. The next Primary assigns a new HQ list; it cannot retarget those captured handles. The cleanup worker does not use the object recycler or a player-proximity gate. Its logged entity count counts deletion commands, not observed removals. Independent reads found no demonstrated array alias, additional 120/300-second deadline, or loop-variable overwrite in this path.

The full Defense function queries nearby House/Building objects, calls `buildingPos -1`, and calculates custom building positions. That engine path is absent from the initial isolated probe. The revised probe applies native `buildingPos -1` and the actual self-contained `customBuildingPositions` function to only the five mapped houses, leaving the direct-created House control unqueried. Native/custom position counts are 11/11, 13/21, 2/2, 1/5 and 2/6 respectively. All still delete normally in the isolated probe. These queries alone therefore do not establish the explanation for the full-mission retained references; active AI/pathfinding and the broader mission remain unisolated differences.

Bohemia's [`deleteVehicle` documentation](https://community.bistudio.com/wiki/deleteVehicle) describes next-frame nullification and permits deleting created buildings; it does not document a general retained-building exception. Its [`createSimpleObject` examples](https://community.bistudio.com/wiki/createSimpleObject) also delete simple objects with `deleteVehicle`. Neither reference supports accepting owner 0 alone as evidence of successful cleanup.

## Cleanup disposition

The successful full cycles record original identities/positions/rays, Deleted events, fresh `allMissionObjects`/`nearestObjects` membership and original network-ID resolution. Their alternative to a null reference is restricted to a captured House with owner 0, an observed Deleted event, an original ID that no longer resolves, absence from both fresh world queries and no original geometry intersections. All conditions must hold, with valid identity/presence/geometry established before deletion. Other object types retain the null requirement. Six retained House handles satisfy every condition in the earlier cycle; three do so in the final source cycle. The latter are one `Land_Cargo_HQ_V4_F` and two `Land_Cargo_Patrol_V4_F` objects, with 7/9/9 geometry hits before deletion and zero afterward. This measures physical and network removal directly and corrects the initial all-null fixture assumption.

The exact engine reference-lifetime mechanism remains unisolated; the evidence does not establish a general exception for all buildings. No wait extension, hidden-object workaround or production deletion change was needed.

## Mapper comparison

Before applying the proposed correction, `fn_serverObjectsMapper.sqf` has no diff from the checkout's `origin/main`. SYS-09 is a baseline defect discovered during this remediation campaign, not an introduced contributor regression.

The mapper creates fresh ordinary objects at temporary negative coordinates, then applies direction and position twice before upright/pitch-bank and simulation settings. The focused native contrast first corrected initial creation for resolved-class Houses on land. A subsequent server-side position refresh did not correct the separate client tilt discrepancy and is absent from the final candidate. Existing placement passes, recycler behavior, callbacks and instrumentation remain intact. Water and non-House creation paths retain their original behavior; their position conventions and physical collision behavior are outside this demonstrated defect.

The verified candidate publishes the original mapped House's final direction/up vectors through the existing server-authored entity-state snapshot after its callback. It captures the object reference before the callback and reads vectors afterward, so an array-returning callback cannot hide the changed House. The publisher and receiver accept an optional validated fifth field while preserving the original feature, face and spawn-handler fields. A single entity-bound JIP entry holds the complete snapshot and follows the existing object-deletion cleanup policy. The receiver applies the orientation locally and rejects remote senders other than the server. The publisher reads, validates and queues its fixed-size snapshot atomically, preventing a suspended older publication from being queued after a newer one.

The expanded probe uses a callback that changes the windmill's pitch/bank and returns an array, then changes its orientation again and replaces feature type 1 with 2. Saved geometry and transform expectations are rebuilt after that actual vector update. Both initial publication and replacement must precede a genuinely later second client. Current and late clients check actual native vectors and geometry, reject a real forged remote-client packet, and observe deletion. A fixture observer calls the exact frozen receiver with inherited native remote context and records authenticated payload plus `isRemoteExecutedJIP`; the late client must receive real JIP delivery. Feature evidence is transport through the actual application path, not a native visual-state query: there is no supported `getFeatureType` getter. The invalid getter assumption was caught and removed before engine execution.

The passing command is `python tests/ia-update/run.py hq-delete --players 2 --client-start-gap 75 --timeout 300`. The private fixture keeps the production receiver's remote-execution `jip=0` configuration; actual server-authored publication still reaches the later client, rather than relying on a more permissive fixture setting. The focused run verifies the complete proposed mapper bytes from its extraction manifest alongside the frozen production publisher/receiver. It does not by itself prove full mission startup or lifecycle behavior after the mapper change.

The subsequent final-source integration cell `7a98937cbfa8` supplies that startup and lifecycle evidence, using the explicitly recorded `reviewed-scout-v1` display control. It verifies genuine human/HC connections, native activity transitions, worker/reservation retirement, support epochs and old-HQ physical cleanup. This remains a local, low-population forced-Defense/cancellation test; water/non-House placement changes, recycler-hit reuse, sustained combat load and another client joining after object deletion are outside the focused claims.

After application, an independent byte comparison verifies the production mapper equals the passing candidate, SHA-256 `6506ec48e2153d843fa82826fb94b82512f8b5d06803dae8e09c516159110284`. The extractor recognizes the complete fixed source and emits identical corrected bytes plus the exact inverse baseline. `git diff --check` also passes.

When production contains the exact complete correction, it emits that as the corrected variant and reverses the changes to obtain the baseline. The probe requires a baseline discrepancy to reproduce and keeps strict proposed position, geometry, network identity, yaw/up and deletion checks on both machines. Both incomplete variants remain failed native runs; the windmill orientation threshold has not been relaxed.

That supported the unsuccessful refresh experiment, but did not establish the House pitch/bank case.
